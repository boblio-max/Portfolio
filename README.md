# Portfolio — Nikhil Mahankali

Live-data science / robotics portfolio. No mock data — every commit count, activity graph, and repo card comes from the real GitHub API via a local Node server.

**Repo:** `boblio-max/Portfolio`

## What it does

- **Overview (`#/all`):** total commits, active days, repo count, contribution graph, featured projects, recent commits
- **Hardware (`#/hardware`):** same views filtered to hardware / robotics repos (CORI, ORBS, LLM CAD Agent, etc.)
- **Repositories (`#/repos`):** all ~45 tracked repos with instant search, language, stars, last activity
- **Activity (`#/activity`):** day-grouped commit feed, with `?scope=hardware` filter
- **Project detail (`#/project/:id`):** per-project commits, stats, linked repos
- Light / dark toggle, GitHub-style contribution graph with tooltip + popover

## Stack

Zero dependencies. Vanilla HTML + CSS + JS frontend, Node built-in `http` + `fetch` backend.

- `index.html`, `style.css`, `script.js` — shell, styles, hash router
- `js/` — `api.js`, `activity.js`, `repositories.js`, `projects.js`, `components.js`
- `server/server.js` — static file server + `/api/*` JSON API + file cache
- `server/github.js` — server-side GitHub sync (token never leaves the server)
- `server/config.js` — tracked repos, categories, hardware set, featured projects
- `server/cache.json` — generated by sync, gitignored

## Quickstart

Requires Node 18+ (uses global `fetch`).

```powershell
# 1. Configure (token raises quota 60/hr -> 5,000/hr, required for ~45 repos)
Copy-Item .env.example .env
# edit .env: GITHUB_USERNAME=boblio-max, GITHUB_TOKEN=..., PORT=3000

# 2. Start
node server/server.js
# -> http://localhost:3000

# 3. Sync real data (in another terminal)
Invoke-RestMethod -Method Post http://localhost:3000/api/sync
```

Open `http://localhost:3000/#/all`. If you skip sync, the API returns `503` with "No data synced yet".

## API

| Endpoint | Description |
|---|---|
| `GET /api/health` | Cache status + `generatedAt` |
| `GET /api/summary?scope=hardware` | Total commits, active days, repo count |
| `GET /api/repositories` | All repos + per-repo stats |
| `GET /api/activity?scope=hardware&repo=<key>` | Activity days, ascending |
| `GET /api/commits?repo=<key>&limit=30&scope=hardware` | Newest-first commits (max 100) |
| `GET /api/projects` / `GET /api/project?id=<id>` | Curated featured projects |
| `POST /api/sync` | Re-fetch all tracked repos (last 12 mo, up to 300 commits/repo) |

## Configuration

All curation lives in `server/config.js` — no code changes needed:

- `TRACKED` — `{ name, owner, repo }` GitHub coordinates
- `CATEGORIES` — tags per repo key
- `HARDWARE` — set of keys shown in hardware view
- `FEATURED` — home-page projects (`showOnHome: false` hides)

## Notes

- `.env` and `server/cache.json` are gitignored. Copy `.env.example` to start.
